# Правила проекта

Эти правила действуют для всей работы над проектом в этом каталоге.

## 1. Работа с Git

- Работаем с Git, но все команды, меняющие состояние Git, выполняет пользователь.
- Ассистент не выполняет `git add`, `git commit`, `git push`, `git init` и другие команды, меняющие состояние Git или репозитория.
- Ассистент может читать состояние и историю репозитория: `git status`, `git diff`, `git log` и аналогичные команды только для чтения.
- Ассистент может редактировать файлы проекта в рамках согласованной задачи.

## 2. Инструкции для Git после каждого этапа

- После каждого этапа ассистент указывает, какие файлы нужно добавить в Git.
- Ассистент предоставляет конкретные команды и осмысленное сообщение коммита, соответствующее выполненным изменениям.
- Пользователь самостоятельно выполняет эти команды.

## 3. Запуск тестов

- Ассистент запускает тесты только после согласия пользователя.
- Перед запросом согласия ассистент объясняет, какие проверки хочет запустить и зачем.
- Если тесты не запускались, ассистент прямо сообщает об этом в отчёте.

## 4. Самопроверка соблюдения правил

- Перед действиями ассистент сверяется с правилами проекта.
- В конце каждого этапа ассистент просматривает изменения и проверяет, не нарушены ли правила.
- Если нарушение произошло, ассистент прямо сообщает о нём.
- Самопроверка сама по себе не включает запуск тестов и не заменяет согласие на их запуск.

## 5. Работа по этапам

- Перед этапом ассистент кратко описывает задачу и ожидаемый результат.
- После этапа ассистент сообщает, что сделано, что проверено и что осталось.

## 6. Сохранение посторонних изменений

- Ассистент не перезаписывает и не откатывает работу пользователя.
- Ассистент не делает переделки, не связанные с согласованной задачей.

## 7. Хранение секретов

- Токены бота, пароли и ключи не должны попадать в репозиторий.
- Секреты храним в локальных переменных окружения; локальные файлы с секретами исключаем из Git через `.gitignore`.
- В примерах конфигурации, включая `.env.example`, используем только заглушки.

## 8. Согласование значимых решений

- Выбор стека, использование платных сервисов, изменение согласованных функций и публикацию приложения обсуждаем и согласовываем с пользователем до выполнения.

## 9. Достоверность отчётов и демонстрационных данных

- Ассистент отделяет сделанное от проверенного.
- Ассистент не заявляет «всё работает», если это не проверено.
- Демо-данные и имитацию оплаты явно обозначаем.

## Формат отчёта после этапа

1. Результат: что сделано и что осталось.
2. Проверки: что проверено и запускались ли тесты.
3. Соблюдение правил: результат самопроверки и нарушения, если они были.
4. Команды Git для пользователя: файлы, команды и сообщение коммита.
